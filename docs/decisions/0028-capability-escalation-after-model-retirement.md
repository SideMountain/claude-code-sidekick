# ADR-0028: モデル退役後の能力エスカレーション再定義（検証量 ladder + 凍結判定 corpus）

## ステータス

採用（2026-07-04）。前提: ADR-0023/0024/0025（文脈経済・budget-gate）、ADR-0027（公式スキル採用とラップ配布）。context-economy.md §8 と auto-implement の R2 運用を本 ADR が改訂する。

## 背景

context-economy.md §8 は難所（R2 閉集合）での動作として「必ず上位モデルを使う」を不変条件としてきた。この設計には構造的な脆弱性がある。

1. **上位 tier モデルの可用性は外部依存である**。提供形態・契約・モデル世代交代により、上位 tier へのアクセスは恒久ではない。可用性が失われた瞬間、「難所は上位モデルへ」という安全機構は実行不能になり、silent に単発判断へ縮退する。個人 brain の原則「外部依存は失敗する前提で設計する」に照らすと、能力エスカレーションをモデル tier に一点依存させるのは境界層のない外部依存と同型の欠陥である。
2. **判定品質の基準器も上位モデルに依存していた**。判定一致率測定（被測定構成の判定を基準判定と突き合わせ、verdict の完全一致率を出す手続き。手順は `tests/fixtures/judgment-corpus/README.md`）は「上位モデルの判定」を比較基準に使う設計であり、上位モデルが利用できなくなると測定自体が不可能になる。
3. 上位/標準モデルのブラインド A/B 実測（2026-07-04・6 判定）で、品質差は**事実忠実性に集中**することが確認されている。差の主軸が「推論の深さ」より「一次ソース確認の規律」にあるなら、その大部分は検証手続きの構造化で代替できる見込みがある（ただし判定一致率の実測で裏づけるまでは見込みに留まる）。

## 決定

### 決定 1: 能力エスカレーションを「モデル tier」から「検証量 ladder」へ再定義する

難所（R2 閉集合）での不変条件を「必ず上位モデル」から「**単発判断の禁止 + 難所カテゴリに応じた検証量エスカレーション**」に置き換える。

| レベル | 対象 | 動作 |
|---|---|---|
| L1（最低線） | 全難所 | R3 敵対検証を 1 本以上発火 |
| L2 | 設計判断・矛盾裁定 | 独立 3 票の多視点検証（correctness / 安全・セキュリティ / 再現性・実行可能性。同一プロンプトの複製は票と数えない） |
| L3 | root-cause・「動く」の裁定 | **実行を arbiter にする**: 実走・テスト・fixture で決着する。読み判定のみでの確定を禁止 |
| L4 | マージ可否・リリース可否（最終 judge） | 多エージェント裁定（利用可能なら公式 /code-review ultra）+ min() 集計 |

- 実行モデルは常に**可用最上位構成**（その環境で使える最上位の model + reasoning effort）。rules / skills の「上位モデル」という表現は「可用最上位構成」に置換し、特定 tier の存在を前提にしない。
- budget-gate THROTTLE 時は票数のみ縮退し、縮退を ledger に記録する（ADR-0024/0025・silent drop 禁止）。L1 の 1 本と L3 の実行 arbiter は縮退対象外（正しさの下限）。

### 決定 2: 凍結判定 corpus を判定品質の恒久基準器とする

- `tests/fixtures/judgment-corpus/` に、退役前の最上位モデル（claude-fable-5・Mythos-class）が確定した判定 17 件を凍結する（レビュー総合判定 / 難所判定 / release 温度感 / 知識還流 / 無人実行入口の 5 カテゴリ）。
- **append-only**: ケース追加は新 ID のみ。既存判定の別モデルによる再生成・上書きは禁止（基準器の意味が失われる）。前提 rubric の改訂でケースが陳腐化した場合は retired 付記で測定対象から外す（削除しない）。
- 判定一致率はこの corpus に対して測定する。ハーネス変更・モデル交代のたびに同一基準で回帰測定できる。

### 決定 3: 難所判定を機械 force-flag で補強する

難所かどうかの判定自体が prose 裁量である限り、標準モデルが難所を見落とすと R3 以降が丸ごとスキップされる。決定的検査 `.claude/scripts/detect-hard-spot.sh`（パス・キーワードの grep）を前置し、ヒットした場合は**モデルの自己判定に関わらず難所として扱う**（force-flag）。モデル判定は force-flag に追加する方向のみ許す（機械が難所と言えば難所。機械が沈黙してもモデルが難所と判断すれば難所）。

### 決定 4: R4 事実忠実性ゲートを実装経路に拡張する

A/B 実測が示した品質差の主軸（事実忠実性）に対し、R4 ゲートの発火点を出力時（ゲート 2）だけでなく**編集の直前**に置く: 変更対象の関数・シンボル・設定キーを当該セッションで Read していなければ、編集前に Read する。新規に呼ぶ外部 API・コマンドは一次ソース（公式ドキュメント・`--help` 実行）を見てから使う。

## 選択肢と却下理由

- **退役モデルのシステムプロンプト（外部抽出物）の移植**: モデルの推論能力は重みにあり、システムプロンプトの移植では転写できない。抽出物は真正性が検証不能で、consumer 製品向けの内容が大半を占め、ccs の対象領域と重ならない。provenance 不明のテキストを OSS リポに取り込む負債も大きい。却下。
- **常時最大検証（全タスクで L2-L4 相当）**: trivial な変更にも多票検証を課すのは文脈経済（ADR-0023・trivial-gating R8）に反し、cap 消費が非対称に増える。難所閉集合 + force-flag の条件発火で必要十分。却下。
- **現状維持（上位モデル前提の R2）**: 背景 1 の通り、外部依存の消失で安全機構が silent 縮退する。却下。

## 検証

- 凍結 corpus に対する標準モデル + harness のブラインド初回測定を実施し、ベースライン一致率を `tests/fixtures/judgment-corpus/README.md` の表と `results/` に記録する（測定手順も同 README）。
- 消失テスト（R3）: 「必ず上位モデル」を削除することで消える検証は「難所での高能力判定」だが、L2（多視点 3 票）・L3（実行 arbiter）・L4（多エージェント裁定）がその代替として明示的に配線されており、無検証の空白は生じない。縮退時も L1 + ledger 記録が下限として残る。
