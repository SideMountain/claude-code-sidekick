# ADR-0033: 文書ガバナンス（文体標準・読者宣言・単一ソース原則）

## ステータス

採用（2026-07-10）。前提: `.claude/rules/oss-doc-authoring.md`（公開ドキュメントの作法）、ADR-0014（ADR は下流に配布しない）、ADR-0030（内部計画文書の非配布）、`.claude/docs/anti-slop-charter.md`（W 系 = 文書 slop の決定的検知・姉妹関係）。

## 背景

リポ全体の文書棚卸し（README 2 本・`docs/` 9 本・`.claude/docs/` 7 本・stack pack 2 本・`REVIEW.md`・brain テンプレート）で、読み物としての一貫性を損なう構造問題を 4 点確認した。

1. **思想の背骨の多重化**。目的（北極星）・3 動詞ループ・認知→強制→検知・検証 ladder が `docs/design.md` / `docs/lifecycle.*.md` / `brain/thinking.md` / README にほぼ同内容で並立し、どれが正かの宣言がない。「単一ソース」を自己宣言しながら逐語再掲している対も 3 系統あり（knowledge-reflux ⇔ knowledge-map、current-state-oracle ⇔ context-economy §5、stack pack 冒頭の三重）、cron-setup-guide の Guard 番号表には独自進化（drift）の兆候が出ている。
2. **読者・ジャンルのラベル不統一**。「OSS 利用者向けか、下流 PJ の runtime 向けか、保守者向けか」「思想か、ルールか、手順か」を冒頭で宣言する様式が `.claude/docs/` にはほぼ揃っている一方、`docs/` 層と一部ファイルには無く、読者がファイルの性格を本文から推測するしかない。
3. **導線の欠如**。`docs/` に索引がなく、読み進め順・使い分けが暗黙。
4. **文体の割れ**。敬体・常体の地の文混在（`docs/migrations/` 内 1 本、`docs/design.ja.md` ほか）、英語版 `lifecycle.md` の地の文への日本語残留、規範文書の地の文への口語・砕けた比喩の混入。

## 決定

### 決定 1: 文体標準・表記統一・冒頭ヘッダ標準を oss-doc-authoring.md に規定する

新規 rules ファイルは作らず、既存の `.claude/rules/oss-doc-authoring.md` を拡張する（既存活用。書きぶりの規範は同ファイルが既に担っており、置き場を分けると参照が割れる）。内容は同ファイルを正とする: README は敬体・他は常体、口語の禁止、表記統一表、全 doc 冒頭の読者・役割・ロード条件宣言、逐語再掲の禁止。

### 決定 2: 思想の背骨の単一ソースは design doc とし、役割が分かる名前に改名する

- 背骨（目的・3 動詞ループ・認知→強制→検知・検証 ladder）の正 = `docs/design.md` / `docs/design.ja.md`。lifecycle・brain テンプレート・README は要約 + リンクに縮約する
- `design.md` という名前はファイル名から役割（何のデザインか）が読めないため、**`design-philosophy.md` / `design-philosophy.ja.md` に改名**する。リポ内の参照リンクは一括更新し、既存 ADR 内のリンクもリンク切れ防止の機械修正として更新する（本文の書き換えはしない）

### 決定 3: 用語「北極星」は「目的」に置き換える（英語: North Star → Purpose)

配布物の本文用語として「北極星（North Star）」を「目的（Purpose）」に統一する。ADR-0018 のタイトル・本文は時点の記録として不変とし、索引で現行用語との対応が追えるようにする。

### 決定 4: 既存 ADR は遡及適用の対象外

ADR は時点の判断記録であり、文体標準・冒頭ヘッダの遡及書き換えは記録性を損なう。新規 ADR から適用する。許すのはリンク切れ防止の機械修正のみ。

### 決定 5: 是正の実施体制（指揮者パターン）

規範確定後の機械的書き換え（ヘッダ敷設・文体統一・表記統一）は下位モデルへ委任できる。ただし**重複解消における「どちらを正にするか」の裁定は矛盾裁定（難所 cat3）**であり、レビュー側（可用最上位構成）が決めてから委任する。委任出力には消失テスト（R3③）と忠実性レビューを適用する。

## 却下した案

- **新規 rules ファイル（writing-style.md 等）の新設**: 書きぶりの規範が oss-doc-authoring.md と 2 ファイルに割れ、参照と path スコープが重複する。既存拡張で足りる
- **ADR への全面遡及適用**: 一貫性は最大化するが、31 本の歴史的記録の書き換えは記録性を毀損し、レビューコストも見合わない
- **重複の現状維持（正の宣言のみ追加）**: 変更は最小だが drift の温床が残り、Guard 番号表で既に観測された独自進化を止められない

## 影響

- 本 ADR と同時: `.claude/rules/oss-doc-authoring.md`（文体標準・表記統一・冒頭ヘッダ標準・単一ソース原則・path スコープ拡張）
- 後続 PR: `docs/README.md` 索引新設・冒頭ヘッダ敷設・design doc 改名と参照更新・用語置換（北極星 → 目的）・文体/重複の是正
- 検証: 文体・口語は決定的 grep で検査可能（anti-slop charter W 系への発火パターン追加は advisory・別途）。重複解消は消失テストを通す
