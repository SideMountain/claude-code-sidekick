# ADR-0030: 内部計画文書の非配布ポリシー（docs/plans 廃止）

## ステータス

採用（2026-07-06）。前提: `.claude/rules/oss-doc-authoring.md`（公開ドキュメントの作法）、ADR-0014（sidekick の ADR は下流に配布しない）、ADR-0022（intake routing: backlog / Issue がタスクの正位置）、ADR-0028（凍結判定 corpus の README が測定手順の所在）。

## 背景

sidekick は OSS 配布物である。`docs/decisions/`（ADR）・`docs/`・`README` 等の公開ドキュメントは「完成形の設計とその根拠」を提示する（oss-doc-authoring）。一方 `docs/plans/` には、作業中の診断・実装計画・ドラフト（ワーキング文書）が置かれており、この基準から逸脱していた。構造的な問題は 3 点。

1. **配布物に議論ログが混入する**。ワーキング文書は「以前は X、現在は Y」「Phase 別の進捗」「未確定の検討」といった時系列・思考の揺れを本質的に含む。これを配布物ツリーに置くと、fork した第三者が「完成形の設計」と「開発者の作業メモ」を区別できない。
2. **耐久素材とワーキング文書が同居する**。計測プロトコル（凍結判定 corpus の測り方）や実装素材（検知パターン等）のような長寿命の参照物が、消化されれば不要になる計画文書と同じディレクトリに混ざり、寿命の異なるものが一括で扱われていた。
3. **逆依存が生じる**。配布物（ADR・`tests/fixtures/` の README）がワーキング文書を参照すると、計画を消した瞬間にダングリング参照になる。「消せない計画」が配布物の巻き添えで固定化される。

タスクの正位置は既に定義されている（ADR-0022 intake routing = backlog / GitHub Issue）。設計判断の正位置も定義されている（ADR = `docs/decisions/`）。`docs/plans/` はこのどちらでもない中間物で、役割が重複していた。

## 決定

### 決定 1: 作業中の計画・診断は git 追跡ツリーに置かない

診断・実装計画・ドラフトは、audience と永続性に応じて既存レイヤーへ振り分ける:

- 個人の working context・次セッション用メモ → auto-memory（`MEMORY.md` Backlog、git 非追跡）
- 他人が拾える具体的作業単位 → GitHub Issue（ADR-0022 intake routing）
- 一時的な検討スクラッチ → 非追跡領域（scratchpad 等）

配布物ツリー（git 追跡下の `docs/` 等）には完成形のみを置く。

### 決定 2: 消化済み計画は削除する

計画が実装に反映されたら、計画文書は削除する。決定の恒久記録は ADR、残タスクは backlog / Issue が正位置であり、消化済み計画を配布物に残す理由はない。「1 アイテム＝1 ホーム」（ADR-0022）を計画にも適用する。

### 決定 3: 耐久素材は正位置へ移設する

計画文書内の長寿命な素材は、寿命に応じた正位置へ移してから計画を削除する:

- 測定プロトコル（判定一致率の測り方等） → 対象データの近傍 README（例: `tests/fixtures/judgment-corpus/README.md`）
- 実装素材（検知パターン・rubric 等） → `.claude/docs/`（遅延ロードの参照物）

ADR からの参照は、この移設先（durable な所在）へ向ける。

### 決定 4: `docs/plans/` ディレクトリは廃止する

`docs/plans/` を配布物の構成要素から外す。以後、計画・診断・ドラフトの置き場としては使わない。

## 選択肢と却下理由

- **`docs/plans/archive/` 化（消化済み計画を archive に退避）**: 却下。議論ログ・時系列・思考の揺れが配布物ツリーに残り続け、背景 1 の問題（完成形と作業メモの混在）が解消しない。archive はワーキング文書の寿命を延ばすだけで、配布物としての純度は下がったまま。
- **`.gitignore` 化のみ（`docs/plans/` を追跡外にする）**: 却下。追跡を外すだけでは、耐久素材の移設（決定 3）と消化済み計画の削除（決定 2）という本質的判断を先送りするだけ。移設漏れの素材が非追跡で失われるリスクと、逆依存（背景 3）が残る。
- **現状維持（`docs/plans/` を配布物に残す）**: 却下。oss-doc-authoring の基準から逸脱したまま。fork した第三者に開発者の作業メモを配ることになり、ADR-0014（配布物の純度を保つ）の方針と逆行する。

## 検証

- 配布物（`docs/decisions/`・`.claude/rules/`・`.claude/skills/`・`README`）からの `docs/plans/` 参照が `git grep docs/plans` でゼロになることを確認する。
- 耐久素材が移設先で参照可能であること（測定プロトコルが対象データ近傍の README に、実装素材が `.claude/docs/` に存在すること）を確認する。
- 消失テスト（R3）: `docs/plans/` を廃止することで失われるのは「作業中の計画の可視化」だが、その役割は backlog / GitHub Issue（進行タスク）と ADR（確定判断）へ移管済みであり、無検証の空白は生じない。
