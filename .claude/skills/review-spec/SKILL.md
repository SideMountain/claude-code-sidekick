# /review-spec — 仕様品質レビュー

## 実行方式

このスキルは **Agent ツールで隔離実行する**。
メインコンテキストを保護するため、Agent にこのスキルの全手順を渡し、結果のみ受け取る。

## 目的

API 契約の整合性、仕様書との乖離、破壊的変更を検出する。

---

## 手順

### Step S1: 変更ファイルの特定

```bash
git diff $BASE_BRANCH...HEAD --name-only | grep -E '(api|route|endpoint|schema|prisma)'
```

### Step S2: API 契約の整合性

- [ ] レスポンス型が変更されていないか（既存クライアントへの影響）
- [ ] 必須パラメータが追加されていないか（破壊的変更）
- [ ] エラーレスポンスの形式が統一されているか
- [ ] バージョニング方針（ある場合）に従っているか

### Step S3: 仕様書との乖離

- [ ] 設計書（docs/ または Notion）に記載された仕様と実装が一致しているか
- [ ] ADR で決定された方針に沿っているか
- [ ] CLAUDE.md の不変条件に違反していないか

### Step S4: 破壊的変更の検出

- [ ] DB スキーマの変更がある場合、Expand-Contract パターンに従っているか
- [ ] 既存 API のレスポンス構造が変わる場合、移行期間が設けられているか
- [ ] 環境変数の追加・変更がある場合、ドキュメント化されているか

### Step S5: 出力

```
=== /review-spec 結果 ===

[S1] API契約: OK / 指摘あり / 対象外（API変更なし）
[S2] 仕様書乖離: OK / 指摘あり / 対象外（仕様書なし）
[S3] 破壊的変更: なし / あり（要対応）

指摘事項:
  [BLOCKER] ...
  [WARN] ...
  [INFO] ...
```

---

## Return Contract

### 返すもの
- Step S5 の出力フォーマットに従ったレビュー結果
- 破壊的変更がある場合、移行手順の提案

### 返さないもの
- API 実装の全文コード
- 仕様書の全文内容

---

## Gotchas

- **仕様書がない PJ** — Step S3 は「対象外」として報告。ADR と CLAUDE.md の不変条件のみチェック
- **GraphQL と REST の混在** — スキーマ変更の破壊的変更検出は API の種類によって異なる。先にプロジェクトの API 方式を確認する
