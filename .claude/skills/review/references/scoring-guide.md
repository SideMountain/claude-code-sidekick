# レビュースコア定量化ガイド

/review の総合判定をスコアで定量化するための基準。
将来の STG 自動マージ判定やレビュー品質の追跡に使用する。

## スコア体系

各観点を 0-3 の4段階で評価する。

| スコア | 意味 | アクション |
|--------|------|-----------|
| 3 | 問題なし | そのまま進行 |
| 2 | 軽微な指摘あり（INFO） | 次回以降で対応可 |
| 1 | 要改善（WARN） | 今回 or 次回で対応推奨 |
| 0 | ブロッカー（BLOCKER） | 修正必須。PR作成不可 |

## 観点別スコア

| 観点 | スコア基準 |
|------|-----------|
| Code (C1-C7) | BLOCKER: ルール違反、セキュリティ脆弱性。WARN: DRY違反、マジックナンバー。INFO: 命名改善等 |
| Test (T1-T6) | BLOCKER: テスト未追加（新規ロジック）、全FAIL。WARN: 境界値テスト不足。INFO: テスト名改善 |
| Ops (O1-O7) | BLOCKER: PII露出、ロールバック不能。WARN: ログ不足、リトライ未設定。INFO: コスト最適化 |

## 総合判定の算出

```
総合スコア = min(Code, Test, Ops)

判定:
  3: PR作成可（全観点問題なし）
  2: PR作成可（軽微な指摘あり。対応は任意）
  1: 修正後に再レビュー推奨
  0: ブロッカーあり。修正必須
```

## STG 自動マージの条件（将来）

以下の全てを満たす場合、STG マージを自動化できる:

```
条件:
  1. /review 総合スコア >= 2
  2. テスト全 PASS（TEST_COMMAND 実行結果）
  3. 型チェック PASS（TYPECHECK_COMMAND 実行結果）
  4. [needs-security-review] ラベルが付いていない
  5. PR の変更行数が閾値以内（デフォルト: 500行）
```

1つでも条件を満たさない場合は手動マージ。
