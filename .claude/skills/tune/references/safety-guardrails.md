# 安全ガードレール（HARD・なぜそうするか）

`/tune` の監査・是正で**例外なく**守る制約。これらは敵対的レビューで「テスト剪定の自動化」を攻撃した結果として確立した。違反は設計事故。

> 核心: **green / mutation-0 / flaky なテストは、自動削除して最も危険なもの。** 「効率化」を理由に安全網を外さない。

---

## 1. テスト削除を提案しない（統合/補強/格上げ/quarantine/追加 のみ）

**なぜ:**
- **「落ちない」は成功状態であって冗長ではない。** 2年 green な regression 番人を消すのは、黙って仕事しているテストを狙い撃ちで消すこと。
- **mutation score 0 ≠ 無用。** mutation は合成バグの注入到達範囲を測るだけで、実 race / IO / config / locale / 順序バグはモデル化できない。**mutation は「テストを足すべき場所」の発見にのみ使う。削除根拠にしない。**
- **flaky ≠ 無用。** flaky は多くの場合 SUT（被テスト対象）の race/timing シグナル。quarantine + 調査であって、自動削除ではない。

**従って:** suggestion は「統合 / リファクタ / quarantine / 補強 / 格上げ / 追加」のいずれか。重複テストの統合も「**本数は減らさず重複行のみ削減**」と明記する。

## 2. E2E / integration / regression は棚卸し対象外

UT がモックで消す配線・直列化・認証・実 DB 制約を、E2E/integration は実際に通している。「UT で覆われている」と推論する剪定は、**置き換え不能なテストから先に消す**。これらは curation（レーン③）の対象に含めない。

## 3. 監査は read-only 静的

テストスイート実行・ビルド・PM コマンド・DB接続・`.env` 接触を一切しない。シグナルは grep 件数・ファイルサイズ・パターン密度で取る。理由: 業務コードの副作用（実 DB・課金 API 等）を踏まないため、かつ WSL 等でのスイート hang を避けるため。

## 4. gated 分離 — tier は予算であって品質の床ではない

| 種別 | 定義 | 扱い |
|---|---|---|
| **純利益（gated=false）** | 設定/CI 構成のみ・テスト件数/内容/挙動を変えない | まとめて 1 PR 可。安全 |
| **要ゲート（gated=true）** | コード/テストを変更する | 1件ずつ **worktree + PR + green スイート + 人手OK** 必須 |

**要ゲートは夜間 auto-implement `--dangerouslySkipPermissions` ループの対象外。**
理由: テスト/コードを変更できるエージェントを無人ループに置くと、**落ちるテストを消して red→green** にできる＝「全部 passing」に見える最悪の故障。無人で回してよいのは純利益（設定のみ）だけ。

## 5. mutation score / coverage% を削除根拠にしない

これらは「テスト価値」や「削除可否」を測らない。**不足箇所の発見＝テストを足す用途のみ。** カバレッジ計測コストの削減を語る時も、削除判断には一切結びつけない。

## 6. CI minutes（課金）を増やす施策は明示する

shard 化・ジョブ増は壁時計を縮める一方で **install 反復等で総 minutes を増やす**。spending-limit に抵触している org ではむしろ逆効果。

- **両得（時間↓ かつ 分↓/不変）**: キャッシュ（依存/ブラウザ/ビルド）/ `npm ci` 化 / 1ジョブ内の並列化（fileParallelism）→ 課金逼迫下でも先行してよい。
- **時間↓ だが 分↑**: shard / ジョブ分割（install 反復）→ cost↔time を明示し、ユーザーに選ばせる。

---

## 是正前のバックテスト（剪定系の提案を出す前に）

統合/quarantine 候補を出す前に `git log --follow <test>` + 関連 bug/PR を確認し、**過去にバグを捕まえたテストを実質的に弱めないか**を検証する。確証が持てない剪定はしない。

## 自己検証チェック（レポート提示前）

- [ ] 削除提案は **0 件**か（統合/補強/格上げ/quarantine/追加 に変換済みか）
- [ ] E2E/integration/regression を棚卸し対象から除外したか
- [ ] mutation/coverage% を削除根拠に使っていないか
- [ ] gated=true を夜間ループ対象外と明記したか
- [ ] 分を増やす施策に cost↔time 注記を付けたか
