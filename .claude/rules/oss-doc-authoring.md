# OSS ドキュメントの作法（SOFT）

sidekick は OSS。`docs/decisions/`, `docs/`, `README.md`, `CHANGELOG.md` 等の公開ドキュメントは「議論ログ」ではなく「完成形の設計とその根拠」を提示する。

## 書かない

- **出典のない外部影響への言及**: 「外部エンジニアから指摘」「コミュニティで議論」「他社事例で〜」等。出典が示せない人物・組織への言及は信頼性を損なう
- **議論経緯の時系列描写**: 「以前は X、現在は Y」「壁打ちで判明」「再検討の結果」「Phase X 着手前のレビューで」等
- **思考の揺れ**: 「最初は〜と考えたが、よく見ると〜」「当初の判断を覆して〜」等の back-and-forth

## 書いていい

- **設計上の問題と選んだ解**: 客観的な技術課題と、それに対する決定
- **判断原則・思想**: "既存活用ファースト" "70% で動く" 等の筋の通った原則は OSS でもむしろ価値
- **却下した案の技術的理由**: ADR 標準セクション。技術評価として記述する

## チェック観点

ADR・docs/・README・CHANGELOG・LICENSE を編集した後、以下に該当する記述があれば書き換える:

- 人物・組織への外部影響言及 → 客観的な技術問題として記述
- 「以前は」「壁打ちで」「再検討」等の時系列 → 完成形の設計記述に
- 思考の揺れ → 1 つの判断結果として提示

## 文体標準（日本語文書・ADR-0033）

- **README\* = 敬体**（利用者への語りかけ）。**それ以外の規範・仕様・手順・遅延ロード doc = 常体**。地の文の文体を 1 ファイル内で混在させない（敬体・常体いずれの文書でも、箇条書き・表・手順内の体言止め・常体は許容）
- 口語・俗語を地の文に置かない。例: ぶっちゃけ / 叩く / 〜じゃん / 挿す / 寝てる /「勝手に」（「自動で」の意味での使用）。定義済みの専門用語は除く（例: anti-slop 文脈の「滑り」）。砕けた比喩・キャッチコピーは README の見出しに限定し、規範文書の地の文は中立語で書く
- 対話デモ・引用・検知パターンのリテラルは適用外
- 英語版 doc の地の文に日本語を残さない（対訳 doc は両言語とも単独で読み切れる翻訳粒度を保つ）

## 表記統一（日本語文書）

| 統一形 | 使わない形 |
|---|---|
| テンプレート | テンプレ |
| セッション | session（和文中の単独使用） |
| プロジェクト | PJ（固有語「PJ brain」は除く） |
| Worktree | worktree（和文中） |
| 単発 | 1発・一発 |

コードスパン・コマンド名・ファイル名・hook 名（`git worktree`・`session-start.sh` 等）は対象外。

## 冒頭ヘッダ標準（読者宣言・ADR-0033）

全 doc は冒頭 5 行以内に**読者・役割・ロード条件**を宣言する（`.claude/docs/` の既存様式「遅延ロード・常駐しない・◯◯時に Read する」の一般化）:

- **読者**: OSS 利用者（下流プロジェクトの人間）/ 下流プロジェクトの Claude（runtime）/ ccs 保守者
- **役割**: 思想 / ルール / 手順 / 仕様 / 記録
- **ロード条件**: 常駐 / 遅延ロード（いつ Read するか）/ 非ロード（配布素材・人間のみが読む）

ADR（様式固定の記録・置き場 `docs/decisions/` が役割を宣言する）・LICENSE・CHANGELOG は冒頭ヘッダ標準の対象外。

## 逐語再掲の禁止（単一ソース原則・ADR-0033）

- 同一内容を複数 doc に置くときは、正（単一ソース）を 1 つ宣言し、他方は **5〜8 行の要約 + リンク**に留める。逐語コピーは更新時 drift の温床
- 思想の背骨（目的・3 動詞ループ・認知→強制→検知・検証 ladder）の正 = `docs/design.md` / `docs/design.ja.md`（改名予定名は ADR-0033 を参照）

## 適用外

- `auto-memory`（feedback / project / MEMORY.md）は内部用。経緯を残してよい
- `CLAUDE.md` は配布物だが内部運用ルールも含む。基本このルールに準ずるが、`Lessons Learned` セクションでは経緯描写を許容
- 実装ファイル（コード・スキル本体）はこのルールの対象外
- **既存 ADR**: 時点の判断記録として遡及書き換えの対象外（文体標準は新規 ADR から適用。リンク切れの機械修正のみ可）
- **既存文書の規範違反の是正は専用 PR で行う**: 無関係な編集の「ついでに」直さない（code-quality §1 Surgical Changes と両立させる）。新規執筆と、当該箇所自体を編集する場合はその場で従う
